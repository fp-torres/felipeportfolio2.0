## ⚙️ Pipeline CI/CD

O deploy acontece **automaticamente** a cada push na branch `main` — zero intervenção manual.

```yaml
# .github/workflows/deploy.yml

name: 🚀 Deploy to Production

on:
  push:
    branches: [main]

jobs:
  deploy:
    name: Build & Deploy
    runs-on: ubuntu-latest

    steps:
      - name: ✅ Checkout do repositório
        uses: actions/checkout@v3

      - name: 📦 Instalar dependências
        run: npm ci

      - name: 🏗️ Build de produção (Vite)
        run: npm run build

      - name: 🚀 Deploy via FTP → Hostinger
        uses: SamKirkland/FTP-Deploy-Action@v4
        with:
          server: ${{ secrets.FTP_SERVER }}
          username: ${{ secrets.FTP_USERNAME }}
          password: ${{ secrets.FTP_PASSWORD }}
          local-dir: ./dist/

      # 🔒 config.php com credenciais NUNCA sobe pro repo. Jamais.
```

> Credenciais de API vivem **apenas** no servidor. O `config.php` está no `.gitignore` permanentemente.

## 🚀 Rodando Localmente

### Pré-requisitos

- Node.js `>= 18`
- PHP `>= 8.0`
- Conta de desenvolvedor no [Spotify for Developers](https://developer.spotify.com/)

---

### 1️⃣ Clone e instale

```bash
git clone https://github.com/fp-torres/felipeportfolio2.0.git
cd felipeportfolio2.0
npm install
```

### 2️⃣ Configure a Spotify API

Crie o arquivo `public/config.php` (não será commitado):

```php
<?php
define('CLIENT_ID',     'SEU_CLIENT_ID');
define('CLIENT_SECRET', 'SEU_CLIENT_SECRET');
define('REFRESH_TOKEN', 'SEU_REFRESH_TOKEN');
```

> 💡 Precisa do `REFRESH_TOKEN`? Siga [este guia](https://developer.spotify.com/documentation/web-api/tutorials/code-flow) para gerar o token via Authorization Code Flow.

### 3️⃣ Suba o servidor PHP

```bash
php -S localhost:8000 -t public
```

### 4️⃣ Inicie o frontend

```bash
npm run dev
# ✅ Acesse: http://localhost:5173
```

O app React detecta automaticamente o PHP bridge local. Tudo conectado, pronto pra rodar.
